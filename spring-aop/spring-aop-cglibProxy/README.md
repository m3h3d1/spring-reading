### 2. Description

Cglib is an open-source code generation library for Java. It creates dynamic proxies for classes by generating bytecode at runtime. The target class does not need to implement an interface. It is often used for AOP, method interception, and method enhancement, and it gives a flexible and fast way to create proxies.

### 3. Main Features

1. **Dynamic proxy generation**
   + Cglib generates a subclass of a class at runtime to proxy the target class. The target class does not need to implement an interface.
   
2. **AOP support**

   + Cglib is a common tool for AOP. It uses proxies to intercept and enhance methods, which makes cross-cutting concerns easy to implement.

3. **Bytecode manipulation**

   + Cglib lets us work on the bytecode directly, so we can change the structure and behavior of a class at runtime.

4. **High performance**

   + Compared with the dynamic proxy in the standard JDK library, the proxy classes generated by Cglib are faster. They work on bytecode directly instead of calling methods by reflection.

5. **Proxy without interfaces**

   + Unlike the JDK dynamic proxy, Cglib can proxy classes that do not implement any interface. This gives it more use cases.

### 4. Best Practices

This example uses Cglib to create a dynamic proxy. First, it creates an Enhancer object. Then it sets the superclass of the target object and the callback interceptor. Finally, it creates the proxy object with the Enhancer. The proxy object can call the methods of the target object, and the logic defined in the interceptor runs before and after each method.

```java
public class CglibProxyDemo {

    public static void main(String[] args) {
        // Create an Enhancer object to generate the proxy class
        Enhancer enhancer = new Enhancer();
        // Set the superclass of the target object
        enhancer.setSuperclass(MyServiceImpl.class);
        // Set the callback interceptor
        enhancer.setCallback(new MyMethodInterceptor());
        // Create the proxy object
        MyService proxyObject = (MyService) enhancer.create();
        // Print the class name of the proxy object
        System.out.println("ProxyObject = " + proxyObject.getClass());
        // Call the method of the proxy object
        proxyObject.doSomething();
    }
}
```

A class that implements the `MethodInterceptor` interface defines the behavior of the interceptor. The `intercept` method receives the proxied object, the target method, the method arguments, and the method proxy object. It runs some logic before and after the target method.

```java
public class MyMethodInterceptor implements MethodInterceptor {
    @Override
    public Object intercept(Object obj, Method method, Object[] args, MethodProxy methodProxy) throws Throwable {
        System.out.println("Before invoking method: " + method.getName());
        Object result = methodProxy.invokeSuper(obj, args);
        System.out.println("After invoking method: " + method.getName());
        return result;
    }
}
```

This defines an interface `MyService` with one abstract method `doSomething()`. Then it defines a class `MyServiceImpl` that implements the `MyService` interface and the `doSomething()` method.

```java
public interface MyService {
    void doSomething();
}

public class MyServiceImpl implements MyService {

    @Override
    public void doSomething() {
        System.out.println("hello world");
    }
}
```

In the run result, the proxy object is created, and the logic defined in the interceptor runs before and after the `doSomething()` call.

### 6. Common Problems

1. **Final classes and methods cannot be proxied**

   + Cglib creates the proxy by generating a subclass of the target class, so it cannot proxy classes and methods marked `final`. If the target class or method is `final`, you cannot use Cglib for the dynamic proxy.

2. **Constructors cannot be proxied**

   + Cglib cannot proxy the constructor of the target class. The constructor runs when the object is created, and the proxy object is only created after the target object exists. So the constructor cannot be proxied.

3. **Inner classes cannot be proxied**

   + Cglib cannot proxy the inner classes of the target class. Cglib creates the proxy by generating a subclass, and an inner class cannot be extended.
