### 2. Description

The `MethodMatcher` interface is a key interface in Spring AOP. It decides whether a given method matches a pointcut expression. It defines the rules and logic of method matching. We can implement this interface to customize how methods are matched, and so intercept and run aspect logic for specific methods.

### 3. Main Features

1. **Method matching**

   + Decides whether a given method matches the pointcut expression, that is, whether the method should be intercepted and get extra logic.

2. **Static matching**

   + Methods can be matched statically. This means the matching logic is fixed before runtime and stays the same during the whole life of the application.

3. **Dynamic matching**

   + Some pointcuts must decide at runtime, based on the method arguments or other conditions, whether a method matches. The `MethodMatcher` interface also supports this dynamic matching.

4. **Runtime efficiency**

   + Implementations of `MethodMatcher` should be efficient, especially for dynamic matching, so they do not put too much load on the performance of the application.

5. **Extensibility**

   + The `MethodMatcher` interface is designed to be easy to extend. We can define our own method matching rules and logic for the needs of different business cases.

### 4. Interface Source

The `MethodMatcher` interface checks whether a target method fits the conditions of an advice. It supports static matching and dynamic matching. Static matching is decided before runtime. Dynamic matching is decided at runtime, based on the method arguments and on how earlier advice ran.

```java
/**
 * Part of a {@link Pointcut}: checks whether the target method fits the conditions of an advice.
 *
 * <p>A MethodMatcher can be evaluated <b>statically</b> or <b>dynamically</b>.
 * Static matching involves the method and (possibly) the method attributes.
 * Dynamic matching also makes the arguments of the call available, and can take into account any effect of earlier advice already applied to the join point.
 *
 * <p>If an implementation returns {@code false} from its {@link #isRuntime()} method, the evaluation can be done statically,
 * and the result will be the same for all calls of this method, whatever the arguments.
 * This means that if the {@link #isRuntime()} method returns {@code false}, the 3-arg
 * {@link #matches(java.lang.reflect.Method, Class, Object[])} method is never called.
 *
 * <p>If an implementation returns {@code true} from its 2-arg {@link #matches(java.lang.reflect.Method, Class)} method,
 * and its {@link #isRuntime()} method returns {@code true}, the 3-arg {@link #matches(java.lang.reflect.Method, Class, Object[])} method
 * will be called <i>before every potential execution of the related advice</i>,
 * to decide whether the advice should run.
 * All earlier advice, such as earlier interceptors in the interceptor chain, will already have run, so any change to argument or ThreadLocal state will be available at evaluation time.
 *
 * <p>Concrete implementations of this interface should normally provide proper implementations of {@link Object#equals(Object)} and {@link Object#hashCode()},
 * to allow the matcher to be used in caching schemes, for example in proxies generated by CGLIB.
 *
 * @author Rod Johnson
 * @since 11.11.2003
 * @see Pointcut
 * @see ClassFilter
 */
public interface MethodMatcher {

	/**
	 * Perform a static check to decide whether the given method matches.
	 * <p>If this method returns {@code false}, or the {@link #isRuntime()} method returns {@code false},
	 * no runtime check is made (that is, the {@link #matches(java.lang.reflect.Method, Class, Object[])} method is not called).
	 * @param method the candidate method
	 * @param targetClass the target class
	 * @return whether this method matches statically
	 */
	boolean matches(Method method, Class<?> targetClass);

	/**
	 * Is this MethodMatcher dynamic? That is, must a final call to the {@link #matches(java.lang.reflect.Method, Class, Object[])} method be made at runtime,
	 * even if the 2-arg matches method returns {@code true}?
	 * <p>Can be called when the AOP proxy is created. It does not need to be called again before every method call.
	 * @return whether a runtime match is needed
	 */
	boolean isRuntime();

	/**
	 * Check whether there is a runtime (dynamic) match for this method. The method must already have passed the static match.
	 * <p>This method is called only if the 2-arg matches method returns {@code true} for the given method and target class,
	 * and the {@link #isRuntime()} method returns {@code true}.
	 * It is called immediately before the advice would potentially run, after all advice earlier in the chain has run.
	 * @param method the candidate method
	 * @param targetClass the target class
	 * @param args the arguments of the method
	 * @return whether there is a runtime match
	 * @see MethodMatcher#matches(Method, Class)
	 */
	boolean matches(Method method, Class<?> targetClass, Object... args);

	/**
	 * Canonical instance that matches all methods.
	 */
	MethodMatcher TRUE = TrueMethodMatcher.INSTANCE;

}
```

### 5. Main Implementations

1. **AnnotationMethodMatcher** 

   + This class is a method matcher for methods with a specific annotation. It can be used to create a pointcut that intercepts and enhances the methods with that annotation.

2. **ControlFlowPointcut** 

   + The control flow pointcut defines where advice is triggered in a specific chain of method calls. It lets us say that the advice is triggered only when the control flow meets certain conditions.

3. **JdkRegexpMethodPointcut** 

   + This class creates a pointcut with method matching based on regular expressions. It lets us define matching rules by method name, to decide which methods are intercepted.

4. **NameMatchMethodPointcut** 

   + This class is a matcher based on method names. It lets us define a pointcut by method name patterns. The advice is triggered when the method name matches the given pattern.

5. **AspectJExpressionPointcut** 

   + This class creates a pointcut with the AspectJ expression language. It lets us use more flexible and powerful syntax to define the pointcut. AspectJ expressions support more features, including access to method arguments, exception types, and so on.

### 7. Best Practices

This example gets the method named "setName" and checks it with four different types of method matchers. AnnotationMethodMatcher checks whether the method has a specific annotation. AspectJExpressionPointcut matches the method with an AspectJ expression. NameMatchMethodPointcut matches the method by its name. JdkRegexpMethodPointcut matches the method with a regular expression. Finally, the program prints the match result of each matcher.

```java
public class MethodMatcherDemo {

    public static void main(String[] args) throws Exception {
        Class<MyService> target = MyService.class;
        Method setNameMethod = target.getDeclaredMethod("setName");

        // Use AnnotationMethodMatcher to check for a specific annotation
        AnnotationMethodMatcher annotationMethodMatcher = new AnnotationMethodMatcher(MyMethodAnnotation.class);
        System.out.println("annotationMethodMatcher matches = " + annotationMethodMatcher.matches(setNameMethod, target));

        // Use AspectJExpressionPointcut to match the method with an AspectJ expression
        AspectJExpressionPointcut aspectJExpressionPointcut = new AspectJExpressionPointcut();
        aspectJExpressionPointcut.setExpression("execution(* com.xcs.spring.MyService.*(..))");
        System.out.println("aspectJExpressionPointcut matches = " + aspectJExpressionPointcut.matches(setNameMethod, target));

        // Use NameMatchMethodPointcut to match the method by name
        NameMatchMethodPointcut nameMatchMethodPointcut = new NameMatchMethodPointcut();
        nameMatchMethodPointcut.setMappedName("setName");
        System.out.println("nameMatchMethodPointcut matches = " + nameMatchMethodPointcut.matches(setNameMethod, target));

        // Use JdkRegexpMethodPointcut to match the method with a regular expression
        JdkRegexpMethodPointcut jdkRegexpMethodPointcut = new JdkRegexpMethodPointcut();
        jdkRegexpMethodPointcut.setPattern(".*set.*");
        System.out.println("jdkRegexpMethodPointcut matches = " + jdkRegexpMethodPointcut.matches(setNameMethod, target));
    }
}
```

The `setName` method of the `MyService` class is marked with the `@MyMethodAnnotation` annotation. This means the method has a specific custom annotation.

```java
public class MyService {

    @MyMethodAnnotation
    public void setName() {
        System.out.println("setName...");
    }
}
```

`MyMethodAnnotation` is a custom annotation that can be used on methods.

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface MyMethodAnnotation {
}
```

In the run result, for the "setName" method of the target class, all the matchers (annotation, AspectJ expression, method name, and regular expression) return true. That is, all of them matched the method.

```java

nameMatchMethodPointcut matches = true

```
